# La aplicación en el teléfono — plan de implementación

> **Para quien lo ejecute:** SUB-SKILL REQUERIDA: `superpowers:subagent-driven-development`
> (recomendada) o `superpowers:executing-plans`, tarea por tarea. Los pasos usan
> checkbox (`- [ ]`) para ir tildándolos.

**Goal:** que las trece pantallas se usen en un teléfono de 390 px siguiendo los
quince frames `Móvil / …` de la maqueta, sin romper el escritorio.

**Architecture:** un solo árbol de marcado por pantalla, mobile-first, con un
único corte en `lg:` (1024 px). Donde la maqueta cambia la estructura —los
cuatro listados que hoy son `<Table>`— se usa grid más `display: contents`, que
hace desaparecer al envoltorio móvil en escritorio. Nada de datos cambia.

**Tech Stack:** Next.js App Router, Tailwind v4, shadcn/ui (Sheet, Sidebar,
DropdownMenu), vitest.

**Spec:** `docs/superpowers/specs/2026-08-26-movil-design.md`
**Maqueta:** `design/arandano.pen`. Los ids de frame van en cada task.

## Global Constraints

- **Las medidas salen de la maqueta, no de esta prosa.** Cuando una task nombra
  un frame, hay que leerlo con el MCP de Pencil (`execute` con
  `filePath: design/arandano.pen`) y sacar de ahí los números. Lo que este plan
  fija es la estructura y las decisiones, no el pixel.
- **El corte es `lg:` (1024) y nada más.** Ningún `md:`, `sm:` ni `xl:` nuevo.
  Los `md:` que ya existen en pantallas de aplicación se migran a `lg:`.
- **Mobile-first**: el valor del teléfono sin prefijo, el de escritorio con
  `lg:`. `w-[168px]` → `w-full lg:w-[168px]`. Nunca `max-lg:`.
- **Cero cambios de datos.** Ni schema, ni migraciones, ni server actions, ni
  consultas. Si una task parece necesitar una, está mal entendida.
- **El escritorio no puede cambiar de aspecto.** Está atado al `.pen` píxel a
  píxel y verificado a ojo. Toda task se mira en los dos anchos antes de darse
  por hecha.
- **Cada task termina verde**: `npm test` completo, no sólo el archivo tocado.
- Español en nombres, comentarios y mensajes.

### Geometría compartida, que se repite en todas las tasks

- **Topbar** (`kyXe1`): alto 56, `--card`, borde inferior 1 `--border`,

  derecho 19. H1 17/600 Archivo `line-height 1.2`; subtítulo 11/400

  borde `--input`; el primario rellena `--primary` y ocupa el ancho sobrante.

```ts
export type Paso = 'carrito' | 'cobro'

export function urlConPaso(actual: string, paso: Paso): string
```

- [ ] **Step 1 — tests que fallan.** En `paso.test.ts`, sobre las dos funciones
  puras (el hook no se testea: no hay jsdom en este repo y no se reintroduce):
  `pasoDeUrl('?paso=cobro')` da `'cobro'`; `'?paso=cualquiera'`, `''` y
  `'?q=x'` dan `'carrito'`; `urlConPaso('/vender?q=iph', 'cobro')` conserva
  `q` y agrega `paso`; `urlConPaso('/vender?q=iph&paso=cobro', 'carrito')`
  **saca** el parámetro en vez de ponerlo en vacío. En
  `punto-de-venta.test.tsx`, sobre el fuente: el componente importa
  `usePasoDeCobro` y **no** importa `useRouter` ni `redirect` — el camino de
  `router.push` es justo el que remontaría el carrito.
- [ ] **Step 2** — correr y ver fallar.
- [ ] **Step 3 — implementar.** `usePasoDeCobro` se apoya en
  `useSyncExternalStore`, igual que `hooks/use-mobile.ts` y por la misma razón:
  es el mecanismo que React documenta para leer una API del navegador sin
  romper el render del servidor ni el hidratado. `getServerSnapshot` devuelve
  `'carrito'`; `getSnapshot` lee `window.location.search`; `subscribe` escucha
  `popstate` **y** un emisor propio, porque `pushState` no dispara `popstate` y
  sin ese aviso el estado no se enteraría de las transiciones propias. Las dos
  transiciones llaman a `window.history.pushState(null, '', urlConPaso(...))` y
  después notifican. **No
  se usa `router.push` ni `useSearchParams`**, y eso lleva comentario: los dos
  disparan un render del server component, y el carrito vive en el estado de
  este cliente.
- [ ] **Step 4** — correr y ver pasar.
- [ ] **Step 5 — commit.** `feat(vender): el cobro como paso, sin perder el carrito`

```ts
 * sino si viene con `lg:` adelante.
 */
const ANCHO = /^(?:[a-z0-9@[\]&>_-]+:)*(?:min-|max-)?(?:w|basis)-\[(\d+)px\]$/

/**
 * Archivos donde un ancho grande sin `lg:` es correcto, con su razón. Un mapa
 * y no una lista: la razón tiene que estar escrita, igual que en SOLO_EN_CSS
 * de test/maqueta.test.ts.
 */
const EXCEPCIONES: Record<string, string> = {
  'app/opengraph-image.tsx':
    'no es una pantalla: es una imagen de 1200×630 que se genera en el ' +
    'servidor y nunca la mira un navegador con un viewport.',
  'app/(app)/servicio-tecnico/[id]/ticket/cuerpo.tsx':
    'el papel de 80 mm mide lo que mide la impresora térmica, no lo que mide ' +
    'la pantalla. Su ancho sale del CSS de impresión.',
}

function fuentes(dir: string, acumulado: string[] = []): string[] {
  for (const entrada of readdirSync(dir)) {
    const completo = path.join(dir, entrada)
    if (statSync(completo).isDirectory()) fuentes(completo, acumulado)
    else if (entrada.endsWith('.tsx') && !entrada.endsWith('.test.tsx')) {
      acumulado.push(completo)
    }
  }
  return acumulado
}

describe('ningún ancho fijo desborda un teléfono de 390', () => {
  // components/ui/ queda afuera: son los componentes de shadcn tal como los
  // copia el registry, y sus anchos los fija cada consumidor.
  const archivos = [...fuentes('app'), ...fuentes('components')].filter(
    (f) => !f.startsWith(path.join('components', 'ui')),
  )

  it.each(archivos)('%s', (archivo) => {
    if (archivo in EXCEPCIONES) return
    const culpables = readFileSync(archivo, 'utf8')
      .split(/[\s"'`{}]+/)
      .filter((token) => {
        const m = ANCHO.exec(token)
        return m !== null && Number(m[1]) > LIMITE && !token.includes('lg:')
      })
    expect(
      culpables,
      `${archivo} declara anchos fijos de más de ${LIMITE}px sin prefijo ` +
        `lg:, así que en un teléfono de 390 desbordan y arrastran la página ` +
        `entera al scroll horizontal: ${culpables.join(', ')}. Escribilos ` +
        `mobile-first — el valor del teléfono sin prefijo y el de escritorio ` +
        `con lg: — o anotá el archivo en EXCEPCIONES con su razón.`,
    ).toEqual([])
  })

  it('EXCEPCIONES no nombra archivos que ya no existen', () => {
    const inexistentes = Object.keys(EXCEPCIONES).filter((f) => !archivos.includes(f))
    expect(inexistentes, `EXCEPCIONES nombra archivos que no están: ${inexistentes}`).toEqual([])
  })
})
```
